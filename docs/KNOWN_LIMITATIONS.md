### 1.2 What *was* verified without a device

| Check | How |
| --- | --- |
| Every screen renders without throwing | 47 component render tests in `tests/components.test.tsx` |
| The persistence layer is correct | 46 repository tests against a real SQLite engine |
| The domain logic is correct | 108 tests across money, calc, reports, format, inventory |
| The validation layer is correct | 45 Zod schema tests |
| The backup format is correct | 20 tests |
| The navigation rules are correct | 13 tests |
| The app compiles and packages | `assembleRelease` completed successfully |
| The JavaScript bundle is produced and minified by Metro | release build output |
| The release APK contains the JS bundle and all 8 fonts | read directly out of `app-release.apk` |
| The release APK ships **no `INTERNET` permission** | `aapt2 dump permissions app-release.apk` — see `BUILD_REPORT.md` |
| The release APK contains the expected native libraries | `libreanimated.so`, `libworklets.so`, `libhermesvm.so`, `libexpo-sqlite.so`, … in all four ABIs |

**The offline guarantee is structural, not merely asserted:**

1. **In the code** — there is no HTTP client, no `fetch` for data, no remote
   image or font URL, no cloud SDK and no analytics. A repository-wide search
   of `src/` and `app/` for `fetch(`, `XMLHttpRequest`, `axios`, `http(s)://`,
   `WebSocket` and `EventSource` returns **no matches**.
2. **In the assets** — all 10 images and all 8 fonts are bundled in `assets/`
   and copied into the APK; nothing is fetched at runtime.
3. **In the shipped binary** — the release variant removes
   `android.permission.INTERNET` and
   `android.permission.ACCESS_NETWORK_STATE` from the manifest, so the APK
   **cannot open a network socket at all**, even if some code tried to.
   This is enforced by `plugins/withOfflineRelease.js`, which writes
   `android/app/src/release/AndroidManifest.xml` with
   `tools:node="remove"`. See `BUILD_REPORT.md` §6 for the `aapt2` output.

The debug variant deliberately keeps `INTERNET`, because a debug build
connects to the Metro dev server over the network. That is a development-only
build; the shipped release artefact has no network capability.

The one network-capable surface that remains in the release build is the
**system share sheet**, which the user opens explicitly. It is an Android
`Intent` handed to another app — it does not use this app's own network
stack and is not covered by the `INTERNET` permission.

## 2. Known deviations from the reference

### 2.1 Visual

| # | Deviation | Reason | Impact |
| --- | --- | --- | --- |
| L1 | Inactive product thumbnails use `opacity: 0.5` instead of `grayscale(1)` | React Native has no CSS filter API | Low |
| L2 | Tabular numerals rely on `fontVariant` where supported and fixed letter spacing otherwise | React Native has no `font-variant-numeric` | Low |
| L3 | Sheet and dialog backdrops use a translucent cocoa scrim instead of `backdrop-blur` | No backdrop-blur API in the native stack | Low |
| L4 | Text metrics differ slightly from Chromium | Chromium and Hermes/Skia lay out text differently | Low — fonts, sizes, weights and line heights are identical |
| L5 | Hover states are replaced by press states | Touch devices have no pointer hover | None |

### 2.2 Behavioural

| # | Deviation | Reason | Impact |
| --- | --- | --- | --- |
| L6 | `localStorage` persistence is replaced by SQLite | `localStorage` does not exist on a device | Intended — it is the reason the app is offline-first and durable |
| L7 | The browser phone frame, stage and scroll chrome are gone | They were preview chrome, not application UI | None |
| L8 | Notification preferences are stored but no OS notifications are raised | `expo-notifications` was not in the mandated dependency list; the preferences are persisted and surfaced in Settings | Low — the reference is also a web preview with no notification delivery |
| L9 | No dark mode | The reference defines a single light palette and the requirement is exact visual fidelity | None |

### 2.3 Platform

| # | Deviation | Reason |
| --- | --- | --- |
| L10 | iOS was not built | The requirement names a production **Android** build. The JavaScript, styles and components are platform-agnostic, and `app.json` contains a complete iOS configuration, but no iOS build was attempted (macOS/Xcode required) |

## 3. Build-environment caveats

### 3.1 Windows `MAX_PATH` limitation

The first release build failed while compiling the native C++ for the New
Architecture:

```
ninja: error: Stat(rngesturehandler_codegen_autolinked_build/CMakeFiles/
react_codegen_rngesturehandler_codegen.dir/D_/Bright_Cakes_Mobile_App/node_modules/
react-native-gesture-handler/shared/shadowNodes/react/renderer/components/
rngesturehandler_codegen/RNGestureHandlerDetectorShadowNode.cpp.o):
Filename longer than 260 characters
```

The absolute path was 353 characters. The New Architecture compiles C++ for
every autolinked native library, and the generated object files are nested
deeply under `android/app/.cxx`; with a workspace folder as deep as
`D:\Bright Cakes Mobile App`, those paths exceed the 260-character Win32
`MAX_PATH` limit.

`Filename longer than 260 characters` is the Win32
`ERROR_FILENAME_EXCED_RANGE` error, not a Ninja-specific check.

**Fix (the one Expo documents for this exact error):**

1. Enable long paths in Windows — already set on this machine:

   ```
   HKLM\SYSTEM\CurrentControlSet\Control\FileSystem
     LongPathsEnabled = 1   (REG_DWORD)
   ```

2. Install a CMake package that bundles **Ninja 1.12.1 or newer** (Ninja
   gained long-path support in 1.12.0; the Android SDK's default CMake 3.22.1
   bundles the older 1.10.2):

   ```powershell
   sdkmanager "cmake;3.31.6"
   ```

3. Point Gradle at it:

   ```
   # %USERPROFILE%\.gradle\gradle.properties
   android.cmakeVersion=3.31.6
   ```

   > **Write this file without a UTF-8 BOM.** PowerShell 5.1's
   > `Set-Content -Encoding UTF8` prepends a BOM. Gradle then fails to parse
   > the first property silently and falls back to the default CMake 3.22.1,
   > which reproduces the original failure with no obvious cause. Use:
   >
   > ```powershell
   > [System.IO.File]::WriteAllText(
   >   "$env:USERPROFILE\.gradle\gradle.properties",
   >   "android.cmakeVersion=3.31.6`r`n",
   >   (New-Object System.Text.UTF8Encoding($false))
   > )
   > ```
   >
   > Verify with
   > `([System.IO.File]::ReadAllBytes($path) | Select-Object -First 3) -join ' '`
   > — it must start with `97 110 100`, not `239 187 191`.

4. Delete the stale CMake trees so they are regenerated with the new Ninja:

   ```powershell
   Remove-Item -Recurse -Force android\app\.cxx, android\app\build
   ```

**Result:** the release build completes. No change to the application source
is required, and `android/build.gradle` is left exactly as
`expo prebuild` generated it.

The build log confirms the override was applied:

```
[ExpoRootProject] Overriding CMake version: 3.31.6
```

and every native module compiles with
`C:\Users\karth\AppData\Local\Android\Sdk\cmake\3.31.6\bin\ninja.exe`
(Ninja 1.12.1).

> A custom `externalNativeBuild.cmake.buildStagingDirectory` override was
> also tried — relocating AGP's `.cxx` staging directory to a short path
> outside the workspace. It fixed the library modules (Reanimated, Worklets)
> but **cannot** fix the app module, because the CMake-encoded source path
> alone (179 characters) plus Ninja's fixed `CMakeFiles/<target>.dir/`
> segment (93 characters) already exceeds 260 no matter where the staging
> directory is placed. The Ninja upgrade is the correct fix and the override
> was removed.

**Reproducibility note:** `android.cmakeVersion` lives in the **Gradle user
home** (`%USERPROFILE%\.gradle\gradle.properties`), not in the repository,
and the `android/` directory itself is not committed — it is regenerated by
`npx expo prebuild --platform android` (Expo Continuous Native Generation
convention). A fresh machine must therefore:

1. install CMake 3.31.6,
2. set `android.cmakeVersion=3.31.6` in `%USERPROFILE%\.gradle\gradle.properties`
   **without a BOM**,
3. run `npx expo prebuild --platform android`,
4. build with `android\gradlew.bat assembleRelease`.

Only after steps 1 and 2 will the native build succeed at this workspace
depth. `expo prebuild` also regenerates `android/gradle.properties` and
drops a project-level `android.cmakeVersion` line, which is why the
persistent copy belongs in the Gradle user home.


### 3.2 `babel.config.js` is intentionally absent

The project has **no** `babel.config.js`. `@expo/metro-config`'s Babel
transformer falls back to `require('babel-preset-expo')` when no project Babel
config exists, and `babel-preset-expo` 58.0.24 enables the Reanimated and
Worklets Babel plugins by default (`reanimated: true`, `worklets: true`).
Adding a custom Babel config risks silently disabling the worklet transform.

`babel-preset-expo@~58.0.24` is nonetheless installed as an explicit
devDependency so the transform is pinned and cannot drift.

### 3.3 `app.json` schema changes in SDK 58

`android.edgeToEdgeEnabled` and `newArchEnabled` were removed from the Expo
config schema in SDK 55+. `npx expo-doctor` failed while they were present.
Both were removed from `app.json`; edge-to-edge is now the Gradle property
`edgeToEdgeEnabled=true` in `android/gradle.properties`.

## 4. Release signing

The release build type is configured with the **debug** keystore, because no
production keystore was provided:

```groovy
release {
    // Caution! In production, you need to generate your own keystore file.
    // see https://reactnative.dev/docs/signed-apk-android.
    signingConfig signingConfigs.debug
    ...
}
```

To produce a store-ready APK:

```bash
keytool -genkey -v -keystore brightcakes-release.keystore \
  -alias brightcakes -keyalg RSA -keysize 2048 -validity 10000

# android/gradle.properties
BRIGHTCAKES_UPLOAD_STORE_FILE=brightcakes-release.keystore
BRIGHTCAKES_UPLOAD_KEY_ALIAS=brightcakes
BRIGHTCAKES_UPLOAD_STORE_PASSWORD=…
BRIGHTCAKES_UPLOAD_KEY_PASSWORD=…

# android/app/build.gradle → release signingConfig
signingConfig signingConfigs.release
```

The APK produced here is therefore **installable and fully functional** but
is **not** signed with a Play Store key.

## 5. Architecture items left deliberately

| # | Item | Why |
| --- | --- | --- |
| A1 | No `babel.config.js` | see §3.2 |
| A2 | `android/build.gradle` is left exactly as `expo prebuild` generated it | the MAX_PATH problem is solved by the CMake/Ninja upgrade, not by patching generated files |
| A3 | The `android/` directory is **not** committed — it is regenerated by `npx expo prebuild --platform android` | standard Expo Continuous Native Generation convention; the generated project is fully determined by `app.json` and `package.json` |
| A4 | `src/utils/reports.ts` computes reports in JavaScript over the hydrated snapshot rather than with SQL aggregates | the data set for a single bakery is small; keeping the arithmetic in one tested module guarantees the numbers match the UI |
| A5 | No background sync or conflict resolution | the app is single-device and fully offline by design |
